# Forge UI — слой жестов и индикаторов

**Кому:** Саидислому · **Что:** довести до ума манипуляции F1–F7.
**Сколько:** несколько итераций — так и задумано, поэтому это отдельный проект.

```bash
npm install
npm run dev
```

Откроется харнесс с двумя панелями. Всё.

---

## Что это и чего тут нет

Это **только слой интерфейса**: камера, выбор, жесты, индикаторы, цифры, нумпад.

Движка здесь нет. Профилей цехов нет. Модели данных нет. Сохранения нет.
Это не забыли положить — это сделано специально: так вы физически не можете
сломать то, что не видите, а я могу принять вашу работу, просто заменив папку.

`src/harness/` — фальшивый хост. Он держит пару панелей в памяти и пишет в лог
всё, что слой сообщает наружу. Магнитов, правил и привязок в нём нет — они живут
в настоящем приложении. Если жест плохо чувствуется здесь — это ваша зона, чините.
Если жесту нужен ответ от модели — это моя зона, напишите в конце файла.

## Структура

```
src/
  contract/types.ts   ← НЕ ТРОГАТЬ. Единственная связь с приложением.
  ui/                 ← ВАША ЗОНА. Меняйте свободно.
  harness/            ← фальшивый хост. Можно менять для своих тестов.
```

## Одно правило про числа

Всё, что пересекает границу, — **mm10**: десятые доли миллиметра, целые.
16 мм = 160. 600 мм = 6000.

Сантиметры существуют только на экране, и превращает их **только**
`ui/measure.ts`. Никаких float, никакой второй единицы. Из этих чисел потом
рождаются файлы для станка — ошибка округления здесь становится кривым
отверстием в настоящем фасаде.

---

## Универсальное правило (главное)

Любая манипуляция — перемещение, размер, поворот, фаска, вырез, отверстие —
ведёт себя одинаково:

1. **Во время жеста:** видно число и **пунктирную выноску** от точки старта до
   текущего положения.
2. **После отпускания:** число остаётся и его можно нажать — открывается нумпад
   с уже выделенным значением.
3. **Дальше оно исчезает само**, если только не открыли нумпад.

Новый инструмент показывает число — значит рисует и выноску. Без исключений.

## Что сейчас плохо (по важности)

1. **Ручки модификаторов не таскаются в 3D.** На F6/F7 у выреза есть красные
   ручки по сторонам; сейчас вырез правится только через чипы и нумпад.
   Это самый большой пробел.
2. **Живой зелёный чип во время жеста никто не видел глазами.** Код есть,
   проверить пальцем — не проверяли.
3. **Мелкие панели.** Кубики граней попадают под стрелки перемещения. Стрелки
   уменьшены до 0.6, попадание в кубик выигрывает у гизмо — но на всех размерах
   это не проверено. В харнессе для этого лежит панель «маленькая».
4. **Пины выбора цели** (первый шаг с F4-01) — обычные `+`, нужна нормальная
   иконография.
5. Поворот на любой угол есть через нумпад, но нет вращения перетаскиванием.

## Чего делать нельзя

- Не добавлять толщину, кромку, паз, стяжку — никуда. Толщину даёт профиль цеха,
  интерфейс её только показывает.
- Не округлять и не «примагничивать» в интерфейсе. Все магниты живут в модели.
  Раньше сцена магнитила сама, и два правила дрались — отсюда была
  непредсказуемость.
- Не добавлять `@react-three/fiber` и `drei`. Здесь чистый Three.js,
  `TransformControls` уже подключён.
- Не менять `src/contract/types.ts`.

## Как сдать

Прислать **только папку `src/ui/`**. Больше ничего.

Перед приёмкой прогоняется:

```bash
npm run typecheck
npm run build
```

и на стороне приложения — 40 автотестов и бейдж «✓ чистота профиля». Если бейдж
краснеет, значит конструкция протекла в дизайн, и правка не принимается, что бы
она ни улучшала.

## Если нужно что-то от модели — писать сюда

<!-- пример: «для вращения перетаскиванием нужно, чтобы хост присылал текущий
     угол в градусах отдельным prop» -->

- **F1, вертикальный сдвиг — «высота над полом».** Индикатор считает пол на `y = 0`.
  Если у комнаты пол на другом уровне, хост присылает его через `groundY_mm10`
  (mm10, по умолчанию 0). Горизонтальный сдвиг пол не трогает — он читается как
  расстояние от точки старта.

- **F03, скругление углов.** UI показывает дугу-подсказку и редактор (радиус · связь ·
  ✓ · удалить) и отдаёт спецификацию через `onApplyRound(cornerIds, radius_mm10)`.
  Самого скругления геометрии тут нет: в `contract`/`Panel` нет поля для него — это
  правка модели. Хост принимает спецификацию и режет геометрию (и файлы для станка) сам.

- **F5, обработка кромки (фальц/L-профиль).** UI показывает полосу-подсказку вдоль
  кромки и редактор (ширина · глубина · связь · ✓ · удалить) и отдаёт спецификацию через
  `onApplyChamfer(edgeIds, width_mm10, depth_mm10)`. Резки геометрии тут нет — поля в
  `contract` нет; хост режет фальц по спецификации. Профиль пока один (L-ступень);
  выбор профиля (фаска/скругление) — позже.
